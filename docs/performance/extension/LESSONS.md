# 后续优化的经验

本轮以 `bc58f81` 为起点，承接[前 60 次实验](../RESULTS.md)，新增 20 次候选实验。
具体门槛、原始数据及 commit 见[结果表](RESULTS.md)。下面记录方法及其适用边界，
不把一次机器上的测量当作所有数据分布的结论。

| 经验 | 证据 | 后续做法 |
| --- | --- | --- |
| 优先减少完整的数据遍历和复制 | 上轮 NumPy 直传成功；本轮 18 将 `Signal` 的已有缓冲直接交给 NumPy，配对整体降耗时 15.21% | 检查缓冲所有权和生命周期；保留输入快照及非有限值语义 |
| 利用已有计算结果比更换通用算法更有效 | 上轮宽窗口 quickselect 不稳定；本轮 4 利用已排序样本合并绝对偏差，通过 41.08% 整体门槛 | 优先寻找重复排序、重复扫描；保留精确统计与异常事件顺序 |
| 不能用一个大收益场景掩盖另一场景退化 | 本轮 12 漂移修正快 29.35%，纯偏移慢 22.22%，拒绝 | 同一算子的常见模式一起测，检查每个用例和最差配对块 |
| 连续内存也有准备成本 | 本轮 2 的 FIR 转置原先通过长核基准；短核和无效窗口检查使接受决定撤销 | 将小输入、短核、无效数据比例和临时内存纳入验证 |
| 加条件分支未必能消除准备成本的副作用 | 本轮 16 守卫转置仍未通过扩展性能门槛 | 不无限堆叠分支；保留简单原实现，保存失败补丁 |
| 无分支、迭代器、原地处理都不是自动加速 | 本轮 1、9、13 分别尝试跨步 FIR、原地合并和布尔归约，均失败 | 用实际编译产物判断，不按 Rust 写法推断速度 |
| 对偏斜输入使用有条件的跳转 | 上轮无条件交集前缀搜索令密集交集慢 13%；本轮 8 仅在初始区间不相交时搜索 | 保留密集场景；它靠近 3% 边界，最终再次独立复测 |
| 省掉一个可见步骤不等于整体收益足够 | 本轮 3、5、7、10、11、15 均低于 8% 门槛 | 不因局部更快保留额外复杂度；没有达标就恢复 |
| 合并版本必须再次测量 | 单项实验与最终全套运行中，未改动的函数也出现性能差异 | 保留全套结果、独立复测和相同源码对照，区分已解释与未解释差异 |

下一次实验应先查看本轮的 `results/`、`rejected/`、`history/` 与 `evidence/`。
特别是 FIR 的撤销记录需要与初始成功测量一起读，不能只检索到较快的那次结果。

当前没有新增运行时依赖、unsafe 缓冲、近似统计、并行调度或 GPU 路径。
Python 接口继续持有 GIL；本轮收益来自单次调用内部的处理与数据传递。

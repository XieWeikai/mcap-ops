# 本轮经验

本轮按 30 个实现单元各测 10 次，共 300 个候选。23 轮保留，277 轮拒绝。
原始测量、失败补丁、验证日志和逐项 commit 见 [结果报告](RESULTS.md)。

| 结论 | 实测依据 | 后续使用方式 |
| --- | --- | --- |
| 消除重复排序比反复调排序函数更有效 | Hampel 维护相邻窗口的有序样本；最终随机窗口耗时降低约 90%，宽窗口约 58% | 保留断点重置、NaN 过滤和窗口上限；不要重新引入每帧整窗排序 |
| 先跳过无关前缀 | 稀疏时间对齐、稀疏线性重采样最终降低约 72% / 71% | 有序数据可一次定位首个支持点；普通密集路径也必须一起测 |
| 小缓存适合重复的确定性计算 | 两项 EMA 时间差缓存、按通道身份缓存 topic 匹配通过门槛 | 缓存键必须完整；topic 缓存不能代替逐条时间范围检查 |
| 一种缓存不适合所有输入 | 单 topic 筛选在集成时退化；一行分支恢复直接比较，多 topic 收益仍达标 | 增加单项、空集合等低开销输入，避免缓存本身成为主要成本 |
| FIR 应减少支持检查开销，而不是默认转置整个输入 | 连续有效支持计数通过九类 FIR 用例，消除了两个前缀数组 | 保持原求和顺序；继续检查短核、长核、断点和非有限值 |
| 使用已有库处理数组布局 | ndarray 连续布局复制使非连续 NumPy 重采样从约 2.09 ms 降到 0.65 ms | 保留逻辑顺序、反向切片和输入快照，不引入借用别名 |
| 成熟解码器外围调参通常收益有限 | 图像解码、PNG 编码、视频轮询及线程参数均未通过本轮门槛 | 不把更多参数或更大输出当作优化；记录并保留原实现 |
| 最终产物必须重测 | 78 个 native 用例、21 个 Python 用例；两侧使用相同最终基准，Python 两侧均为 release wheel | 保留孤立轮次结果，也检查合并构建和实际安装包 |

下一轮先读失败记录和输入分布，再提出新的候选。参数扫描是参数扫描，不能
当作不同算法；未达标、未运行或仅修复编译的尝试，不应被记为成功优化。

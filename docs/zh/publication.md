## 公开前迁移

公开前从可达历史中移除了执行别名、带账号的工作路径、系统启动标识等部署信息。
文档改为描述 Linux 的硬件、软件和测量条件；执行位置通过忽略的本地配置或环境变量
提供，不再是仓库中的固定机器。

这次是发布迁移，不是新的优化轮次。保留迁移前 89 个提交及父子关系、全部 380 个实验
决策、测量样本、性能汇总和验收结论。每个对应提交的生产算子源码树逐字节一致。

## 提交引用

改写元信息和文档会改变 Git commit ID。[提交映射](../performance/publication/commit-map.json)
记录每个归档 ID 对应的公开提交。历史报告仍以原 ID 作为稳定归档标识，查阅实际 Git
版本时使用此映射。

参考实现准备脚本和历史候选辅助函数通过 `scripts/history_revision.py` 自动解析归档
ID，仍需完整 Git 历史。映射表不是一个含私有历史的额外分支；提交 ID 变化并不意味着
其中数值实现发生变化。

## 脱敏后的哈希含义

- 测量样本、迭代数、决策、数值结果，以及生产源码/扩展/wheel 哈希不变。
- 文本日志和 JSON 元信息移除标识与绝对路径后，字节可能变化；引用它们的哈希对应
  当前公开的脱敏字节。
- 不在 Git 中的原始 profile 或二进制哈希仍标识原产物，不意味着 Git 包含这些文件。
- 原始恢复 bundle 保存在公开树以外，不作为公开 Release 附件。

不把脱敏日志称为逐字节原件，也不把元信息迁移称为重新执行了 benchmark。性能结论
仍基于原来的测量，不制造新的实验结果。

## 旧克隆的处理

本次有意改写发布历史。旧克隆如有本地工作，应先保留，再优先重新克隆公开仓库。
不要把旧私有历史合并回公开 main。后续贡献和发布使用新的公开 commit ID。
